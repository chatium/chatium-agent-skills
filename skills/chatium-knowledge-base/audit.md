# Аудит: инвентаризация и находки

Аудит нужен, когда пользователь его попросил или когда без него следующий шаг будет неверным. Сам по себе он не повод перестраивать базу.

## Инвентаризация

Собери таблицу по базе: путь файла, название, раздел, тип материала, дата последнего изменения, входящие ссылки. Источник — сам каталог `.knowledge-base/`.

Смотри по уровням, а не по одному файлу: какие базы есть, что лежит в корне каждой, какие разделы пустые, где скопилась свалка.

## Классы находок

| Находка | Как видно | Чем плохо |
| --- | --- | --- |
| Дубли и пересечения | одна тема в двух статьях, совпадающие фрагменты | расходятся со временем, читатель не знает, чему верить |
| Противоречия | разные значения, шаги или сроки в двух местах | ошибки в работе и потеря доверия к базе |
| Пробелы | частые вопросы без ответа | база не решает свою задачу |
| Свалка в корне | много статей прямо в базе, без разделов | ничего не находится |
| Плоская ветка | восемь и более прямых статей, повторяющиеся префиксы | читатель просматривает длинный список |
| Мёртвые записи в `order` | `order` ссылается на несуществующий файл или папку | дерево не ломается, но это след переименования: порядок чтения перестал работать как задумано |
| Порядок «по алфавиту» | важные для чтения статьи не перечислены в `order` | читатель идёт по названиям, а не по замыслу автора |
| Битые ссылки в тексте | ссылка ведёт на несуществующий путь или записана относительно (`./x.md`) | переход не работает: renderer отбрасывает относительный адрес |
| Смешение типов | инструкция и теория в одном тексте | непонятно, что делать, а что просто знать |
| Названия-невидимки | «Общие сведения», «Работа с системой» | по ним не ищут |
| Устаревшее | шаги не совпадают с текущим продуктом, ссылки мертвы | действия по устаревшей инструкции |
| Реестр расходится с базой | вопрос решён в статье, но строка осталась в реестре; либо запись без даты и адресата | следующий читатель считает решённое нерешённым, а долг — забытым |

## Метод

1. Инвентаризация — полный список файлов.
2. Классификация статей по типам — по форме текста, а не по названию раздела.
3. Тематическая группировка — где две статьи про одно, там кандидат на слияние.
4. Карта покрытия — типовые задачи читателей против наличия ответа.
5. Ссылки — битые переходы между статьями, сироты, тупики и записи в `order` без файла.
6. Данные из жизни — обращения, повторяющиеся вопросы; без них аудит отражает вкус проверяющего.
7. Приоритизация по последствиям, а не по объёму текста.

## Приоритет

- **Критично** — вводит в заблуждение, влияет на деньги, доступы, безопасность или обязательства.
- **Важно** — частая задача без ответа либо с устаревшим ответом; дубль, по которому данные уже разошлись.
- **Потом** — стиль, оформление, косметика структуры.

## Отчёт

1. Сводка числами: сколько баз, разделов и статей; сколько дублей, сирот, мёртвых записей в `order`, статей в корне.
2. Топ находок — по одной строке, каждая с путём файла.
3. Таблица: файл | что не так | следствие | что сделать | приоритет.
4. План: что делаем сразу, что следующим этапом.
5. Что не проверялось и почему.

## Правила честного аудита

- Во время аудита не чинить: фиксировать факт и путь.
- Не оценивать авторов — оценивать статьи.
- Не выдавать одну находку за систему: указывай, сколько файлов затронуто.
- Если просмотрена только часть базы, так и скажи.
