# Привязка домена к Chatium

Помоги подключить домен к нужному аккаунту и проверить, что по HTTPS открывается ожидаемый сайт. Отвечай на языке пользователя.

Если домен уже работает, а пользователь хочет показывать другую страницу на `/`, используй [настройку главной страницы через `.chatiumrc`](../chatium-development/routing.md#domain-homepages-with-chatiumrc). `indexPath` выбирает страницу для уже подключённого домена; DNS и привязку аккаунта он не меняет.

## Определи цель и текущее состояние

- Установи точный домен и целевой аккаунт из запроса или подтверждённого контекста. Если их не хватает, спроси до чтения данных аккаунта и изменений. Уточни необходимость `www` или других поддоменов, когда это влияет на результат.
- Используй только имя хоста: без `https://`, порта и пути. Для кириллического домена учитывай ASCII/Punycode при сравнении с данными API и DNS.
- Открой `/s/cdm/` на текущем рабочем адресе целевого аккаунта. Сохрани этот адрес для доступа во время настройки. Экран требует `system:domains:manage`; при отказе нужен пользователь с этим разрешением, например Admin или Owner.
- Проверь, добавлен ли домен, какой способ привязки выбран и какой домен сейчас основной. Если домен уже принадлежит другому аккаунту, сообщи об этом: перенос требует отдельного поручения и доступа к соответствующему аккаунту.

## Выбери способ привязки

| Ситуация | Режим Chatium | Что меняется |
| --- | --- | --- |
| DNS остаётся у текущего провайдера; подключается сайт или отдельный поддомен | `OnlyCert` — «Настройка А записей во внешней зоне» | A-записи нужного хоста у DNS-провайдера; Chatium выпускает сертификат |
| Пользователь хочет передать управление всей DNS-зоной Chatium | `ZoneAndCert` — «Делегирование зоны» | NS-серверы у регистратора; DNS-записи управляются в Chatium |
| Уже используется внешний прокси/CDN с сертификатом | `ProxiedCert` — «Проксирование через внешний сервис с сертификатом» | Сохраняется согласованная схема проксирования; проверяются маршрутизация и сертификаты |

Для домена с действующей почтой, другими сайтами или при подключении поддомена предлагай `OnlyCert`: он позволяет сохранить остальную DNS-зону. Если способ ещё не определён и выбор меняет существующую инфраструктуру, согласуй его до изменения. `External` — внешнее управление; в этом режиме флаг готовности сам по себе не доказывает работу DNS и HTTPS. Используй его только для явно заданной внешней схемы.

NS-серверы и IP-адреса бери из экрана конкретного домена в `/s/cdm/domain/<id>`. Если этих значений нет, получи их у пользователя или через доступный интерфейс Chatium. Не подставляй запомненные IP, NS или CNAME на системный адрес аккаунта.

## Добавь домен и настрой DNS

Через `/s/cdm/` нажми «Хочу привязать свой домен» или «Добавить еще один домен», введи имя и выбери согласованный режим. Для уже добавленного домена продолжи его настройку. Если доступен Source Git checkout, можно использовать API ниже.

**Для `OnlyCert`:** покажи точную таблицу DNS-изменений: тип `A`, имя хоста и каждый IP с экрана Chatium. В зоне `example.com` имя `@` обычно означает `example.com`, а `shop` — `shop.example.com`; сверь формат у провайдера. Изменяй записи только нужного хоста. Устаревшие A, AAAA и конфликтующий CNAME этого хоста проверь перед заменой; посторонние записи, включая MX и почтовые TXT, сохрани. Если включён прокси/CDN, согласуй прямой DNS или настройку `ProxiedCert`: обычный `OnlyCert` проверяет адреса Chatium.

**Для `ZoneAndCert`:** до переключения NS получи полную текущую зону у DNS-провайдера и перенеси необходимые записи в редактор Chatium `/s/cdm/dnsRecords/<id>`. Публичный DNS-запрос не показывает все записи зоны. Сохрани почту (MX, SPF, DKIM, DMARC), проверки владения и записи других сервисов, согласовав конфликты с записями сайта Chatium. Затем замени NS у регистратора на точный список с экрана домена. Для делегирования отдельной подзоны NS задаются в родительской зоне. Если используется DNSSEC, согласуй DS/DNSSEC при смене DNS-провайдера до переключения.

Меняй DNS через доступный инструмент в пределах поручения пользователя. Если доступа нет, дай точные значения и место изменения, дождись сообщения о выполнении, затем продолжи проверку. Привязка сайта не требует включать рассылки или менять MX на Chatium.

## API через `chatium exec`

Используй этот путь только из Source Git checkout нужного аккаунта, с `origin` на его репозиторий Chatium и успешным Source Build для текущего committed `HEAD`. Без checkout используй экран доменов. Подробности исполнения — в [exec.md](../chatium-development/exec.md).

Сверь сигнатуры `@app/account-domain` с доступными typings проекта. Ниже минимальный контракт: `getDomains(ctx)` возвращает домены текущего аккаунта с `id`, `name`, `isReady`, `controlType`, `dnsRecords`, `pathPrefix`, `lang`, `createdAt`. Он не возвращает NS/IP для настройки или подробный статус выпуска сертификата; эти данные смотри на экране домена. Список также не помечает основной домен — проверь его в интерфейсе.

Начни с чтения:

```sh
chatium exec <<'EOF'
import { getDomains } from '@app/account-domain'

return (await getDomains(ctx)).map(({ id, name, isReady, controlType }) => ({
  id, name, isReady, controlType,
}))
EOF
```

Для добавления замени пример на согласованный домен в ASCII и выбранный режим. Существующую запись используй повторно; если её режим отличается от нужного, измени его через экран домена.

```sh
chatium exec <<'EOF'
import { addAccountDomain, getDomains } from '@app/account-domain'

const name = 'shop.example.com'
const existing = (await getDomains(ctx)).find(domain => domain.name === name)
const domain = existing ?? await addAccountDomain(ctx, { name, controlType: 'OnlyCert' })
return { id: domain.id, name: domain.name, isReady: domain.isReady, controlType: domain.controlType }
EOF
```

Добавление меняет аккаунт сразу, без публикации кода. После ошибки или таймаута сначала перечитай список и экран домена: запись могла сохраниться до ошибки сервиса. Продолжай с существующей записью; повторное удаление и создание не является способом ожидания DNS. Для изменения режима, DNS-зоны или синхронизации используй интерфейс, а не выдуманные методы `@app/account-domain`.

## Проверь готовность и основной домен

На экране домена различай этапы:

| Статус | Значение и следующий шаг |
| --- | --- |
| `New` | Ожидает обработки |
| `WaitDelegate` | Ожидает DNS: сверь NS или A с выбранным режимом |
| `Delegated` | DNS принят, ожидается сертификат безопасности |
| `Ready` | Chatium считает домен готовым; проверь сайт по HTTPS |
| `Disabled` | Домен удалён или отключён; выясни причину |

Статус обновляется автоматически; учитывай TTL и время распространения DNS. При задержке проверь фактические ответы DNS и комментарий на экране, прежде чем повторять изменения. Кнопку «Синхронизировать» используй, когда интерфейс сообщает о несогласованности данных.

Из локального терминала можно проверить нужный хост, заменив пример:

```sh
dig +short A shop.example.com
dig +short AAAA shop.example.com
dig +short NS example.com
curl --head --location --max-time 30 https://shop.example.com/
```

Для делегированной подзоны запроси NS именно этой зоны. Если локальный и авторитетный DNS расходятся, проверь ответ авторитетного сервера и TTL. При ошибке HTTPS проверь сертификат на нужное имя и доступность HTTP-проверок `/.well-known/acme-challenge/` и `/s/cdm/verifyHost`, особенно за прокси. Проверка HTTPS должна проходить с обычной проверкой сертификата. HTTP-ответ сам по себе не подтверждает нужный аккаунт: открой страницу в браузере и сверь содержимое. Нужные варианты с `www` и без него проверь отдельно, включая редиректы.

Назначай домен основным только если пользователь этого попросил, после проверки DNS, HTTPS и сайта. На экране есть кнопка «Сделать домен основным». Через API передавай найденный объект домена, а не строку имени:

```sh
chatium exec <<'EOF'
import { getDomains, setAccountPrimaryDomain } from '@app/account-domain'

const domain = (await getDomains(ctx)).find(domain => domain.name === 'shop.example.com')
if (!domain?.isReady) throw new Error('Домен ещё не готов')
await setAccountPrimaryDomain(ctx, { domain })
return { id: domain.id, name: domain.name }
EOF
```

После изменения перечитай экран и проверь ссылку на основной домен. Если на `/` открывается другая страница, перейди к [настройке главной страницы](../chatium-development/routing.md#domain-homepages-with-chatiumrc).

Заверши ссылкой на сайт и проверенным состоянием DNS, HTTPS и основного домена, если он менялся. Если требуется действие у регистратора или ожидается сертификат, укажи конкретный оставшийся шаг и ссылку на экран домена; до успешной проверки не объявляй привязку завершённой.
