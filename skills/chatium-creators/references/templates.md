# ZIP-шаблоны

Шаблон передаёт получателю редактируемую копию решения. В ZIP могут быть страницы,
автоматизация, один скилл или набор скиллов с материалами. Store выдаёт архив,
а агент получателя по запросу может установить и адаптировать скиллы в его проекте.
Опиши зависимости, инструкцию применения и способ проверить результат.

## Шаблон со скиллом

Упакуй каждый скилл целиком вместе с `SKILL.md`, справочниками, примерами и ресурсами,
сохранив относительные ссылки. Укажи в README, какие папки нужно установить, какие
настройки изменить под себя и каким запросом проверить работу. Один из вариантов
структуры ZIP:

```text
README.md
skills/
  brief-editor/
    SKILL.md
    references/
      example-brief.md
```

Путь `skills/` здесь служит для организации файлов внутри архива. Имя `brief-editor`
совпадает с `name` в `SKILL.md`. Пакет остаётся полноценным шаблоном, если содержит
только скилл и материалы к нему. В карточке включи `supportsSkills`, опиши скилл и
выбери его категории. Если другой функциональности нет, укажи `hasFunctionality: false`.
Архив проверь также со стороны получателя по шагам установки ниже.

## Упаковка

Подготовь отдельную папку с выбранными материалами. Не копируй весь checkout вместе с
`.git`, `.env`, `node_modules`, OAuth-сессиями, ключами или клиентскими данными. Сохраняй
нужные исходники, относительные ссылки, лицензии и инструкцию. Для шаблона со скиллом
передай `--include README.md skills` в примере ниже.

Для воспроизводимой упаковки выбранных путей есть штатный скрипт.

Сначала проверь `python3 --version`: Python 3 не гарантирован в виртуальной среде
агента. Если его нет, используй доступный штатный менеджер Python либо переносимый
интерпретатор из официального источника в каталоге временных файлов; не меняй
системный Python и исходники проекта ради запуска упаковщика. После подготовки
интерпретатора запусти:

```sh
python3 <skill>/scripts/package_template.py --root ./prepared-solution \
  --include README.md src assets --output /tmp/my-solution.zip
```

Скрипт проверяет пути, исключает опасные служебные файлы и symlink, создаёт ZIP в стабильном
порядке и выводит состав, размер и SHA-256. Он не анализирует код на утечки секретов и не
доказывает работоспособность шаблона: изучи выбранные файлы и проверь сценарий применения.
При отказе из-за запрещённых файлов очисти отдельный пакет; не отключай проверку.

## Карточка, загрузка, проверка

1. Прочитай категории через `getCreatorCatalogOptions` и имеющиеся шаблоны.
2. Создай черновик `createCreatorTemplate(ctx,{slug,fields:{title,...}})`, если его ещё нет.
   Если у шаблона есть [лендинг решения](lifecycle.md#лендинг-решения), передай его URL в `fields.landingUrl`.
   Slug шаблона — 2–80 строчных букв/цифр/дефисов, начинается буквой или цифрой.
3. Вызови `createCreatorTemplateUpload(ctx)`. URL принадлежит Store **в исходном аккаунте**,
   действует 10 минут и требует multipart POST, поле `Filedata`. Сохрани результат exec
   в временный JSON, не выводи URL в публичный отчёт.
4. Загрузи локальный файл:

   ```sh
   python3 <skill>/scripts/upload_template.py --upload-json /tmp/upload.json --file /tmp/my-solution.zip
   ```

   Результат — `hash` и размер. Скрипт не создаёт карточку. Загрузка через обычный
   `chatium storage upload --protected` создаёт файл в другом контексте хранения;
   для этого сценария используй именно URL, выданный creator SDK.
5. Перечитай карточку и вызови `setCreatorTemplateArchive(ctx,{id,hash,expectedUpdatedAt})`.
   SDK проверяет владение исходным файлом, копирует его в защищённое хранилище центрального
   Store и повышает revision. Нельзя передавать URL или hash чужого архива из каталога.
6. Прочитай `getCreatorSolution` и `getCreatorTemplateArchive(ctx,{id})`. Скачай по временной
   `archiveUrl`, проверь ZIP (`python3 -m zipfile -t FILE`), состав и при необходимости SHA-256.
   Ссылки доступны до 10 минут, их нельзя сохранять как постоянную ссылку на товар.

При новой версии обновляй **ту же карточку** и проверяй увеличенную revision. Повторное
прикрепление того же исходного hash после свежего чтения не создаёт лишнюю ревизию.
После сетевой ошибки проверь revision/архив до повторной загрузки. SDK не хранит историю
архивов и не откатывает автоматически; сохраняй проверенные релизные пакеты у автора.

## Установить скилл из шаблона

По просьбе «установи скилл из шаблона» проведи получение и установку в аккаунте
получателя. Если шаблон уже получен, работай с ним как с покупательской копией.

1. Найди нужный шаблон по ID, slug или названию через `getAvailableTemplates(ctx)`
   в целевом аккаунте. При отсутствии права дай пользователю ссылку на карточку
   для получения. Если пользователь уже передал подходящий ZIP, используй его.
2. Скачай по свежей `archiveUrl` и распакуй во временную папку. Проверь, что пути
   остаются внутри неё, а пакеты состоят из обычных файлов. Прочитай README и
   выбранный `SKILL.md`. Проверь имя, связанные файлы и зависимости.
3. Установи выбранный пакет целиком в каталог скиллов нужного агента. Для
   проектной копии в Codex это `.agents/skills/<name>/`, в Claude Code —
   `.claude/skills/<name>/` в checkout выбранного аккаунта. Для другого агента
   используй его способ подключения скиллов. Используй локальное имя пакета без
   префикса `chatium`: этот префикс зарезервирован в каталогах, которые обновляет
   `chatium get-skills`. При переименовании согласуй имя папки, `name` и ссылки на
   скилл. Если имя уже занято, сравни файлы и сохрани правки получателя.
4. Проверь, что `SKILL.md` и материалы на месте. Убедись, что агент в выбранном
   проекте обнаруживает скилл по имени, и проверь его простым запросом без записи
   данных. При необходимости открой новый сеанс. Сообщи путь установки и результат
   проверки. Если проверить загрузку в агенте не удалось, укажи, что файлы добавлены.

Получатель может менять `SKILL.md` и остальные файлы своей копии. Пример запроса
к агенту: «Установи скилл “Редактор брифов” из моего шаблона и адаптируй под наши отчёты».
Агент устанавливает пакет и вносит правки в проект получателя по его поручению.

### Получить ZIP в аккаунте покупателя

`getAvailableTemplates(ctx)` возвращает доступные аккаунту платные и бесплатно полученные
шаблоны и актуальные временные ZIP-ссылки;
при отсутствии действующих прав — `[]`. Разрешён серверному коду аккаунта, плагинам и jobs,
не требует Creator connection. Через CLI нужен `chatium exec --write` для выдачи ссылок.
Других параметров, включая accountId, нет. Основные поля: id/slug/title, archiveUrl,
urlExpiresAt, revision, finishAt (null = бессрочно), shortDescription/description, landingUrl (или null), creator, categoryIds,
languages, contentMode, skills и updatedAt. Ссылка действует до 10 минут, но не дольше
оставшегося доступа; после истечения вызови SDK заново. Ошибку чтения не заменяй `[]`.

Новая ревизия доступна как свежий образец. Для обновления сравни её с применённой
ревизией и перенеси нужные изменения, сохраняя правки получателя. После окончания
доступа ранее скачанная и установленная копия остаётся у получателя.
Цена и предложения настраиваются через [кабинет](commerce.md), не через patch карточки.
