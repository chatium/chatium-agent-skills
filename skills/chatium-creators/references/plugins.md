# Подготовка плагина

Сначала определи конкретную папку, функциональность, зависимые приложения и предполагаемую
аудиторию. Для переноса уже созданного решения сохраняй его поведение. Не регистрируй весь
аккаунт, служебные папки или чужой модуль только потому, что они появились в списке.

Плагин — зарегистрированная папка исходного аккаунта, не ZIP для Store. Подготовь код
и конфигурацию по `chatium-development`, проверь актуальные platform typings, права,
маршруты и использование SDK. Параметры конкретного клиента, секреты, личные записи и
привязки контактов не должны становиться общей конфигурацией тиражируемого приложения.
Предусмотри настройки/первый запуск там, где новому аккаунту нужны собственные значения.

Если приложение поставляет скиллы, положи их в `.skills` **в корне регистрируемой
папки** до сборки и проверь фактическую загрузку после установки. Структура, имена и
проверка описаны в [платформенном контракте скиллов](skills.md#скиллы-внутри-плагина).

## Регистрация

1. Проверь изменения локально и доставку кода по правилам проекта. Native discovery
   видит папки **опубликованного кода аккаунта**. Наличие папки локально или только в
   preview-ветке не доказывает её доступность регистрации. Не публикуй production-код
   исключительно ради обхода отсутствующей папки без соответствующего поручения.
2. Вызови `getCreatorPluginSources(ctx)`: `directories` — кандидаты, `apps` — уже
   зарегистрированные приложения с `id`, `slug`, `directory`.
3. Вызови `registerCreatorPlugin(ctx, { directory, slug })`. Slug без автоматически
   добавляемого `dev-`, минимум 5 символов, строчные латинские буквы, цифры, одиночные
   дефисы, первая буква, последний символ не дефис. Передавай точную папку из discovery.
4. SDK регистрирует **приватное** приложение платформы и создаёт карточку в подключённом
   кабинете. Поле `id` — ID карточки Store, `pluginId` — отдельный числовой ID платформы.
   Не придумывай PID и не подменяй один идентификатор другим.
5. При повторе того же directory/slug SDK переиспользует нативное приложение/карточку.
   После таймаута сначала перечитай источники и карточки: регистрация приложения и запись
   карточки не составляют одну платформенную транзакцию. Плагин другого креатора не
   перепривязывается; обратитесь к владельцу/поддержке по конфликту.

Чтобы добавить существующий плагин этого аккаунта, используй ту же регистрацию с его
directory и исходным slug. Минимум 5 символов относится к новым регистрациям; существующие
короткие slug сохраняются. Другой подключённый аккаунт может редактировать карточку,
но регистрировать и устанавливать приватный плагин можно только из его исходного аккаунта.

## Проверка и карточка

По поручению испытать плагин в исходном аккаунте вызови `installCreatorPlugin(ctx, {id})`.
Результат содержит URL и полный список заявленных `permissions`; сообщи пользователю
факт установки и права. Это установка в собственный аккаунт, не публикация для всех.
Не обещай, что вызов проверил безопасность кода. Для установки чужого опубликованного
приложения есть отдельный сценарий `chatium-development/store-plugin-install.md`.

Открой URL и проверь основной сценарий, настройки нового аккаунта и отсутствие зависимости
от секретов/данных автора. Затем заполни карточку через `updateCreatorSolution`: название,
краткое и полное описание, языки, категории, изображения и при необходимости
[метаданные скиллов](skills.md#поддержка-в-карточке-store). Полное описание должно
объяснять результат, подготовку, ограничения и поддержку.

Для платного плагина свяжи [условия тарифа](commerce.md#условия-тарифа-и-опции-плагина)
с [проверками доступа и квоты в коде](plugin-commerce-sdk.md). Назначение тарифа в карточке
выдаёт права после покупки, а защита маршрутов и расход ресурса задаются в самом плагине.

Исходный приватный slug `dev-*`, статус карточки Store и глобальная доступность приложения
платформы — разные состояния. Заявка не переводит приложение автоматически в публичный
режим. Поддержка/модерация должна завершить публикацию платформенного приложения и карточки.
Не переименовывай глобальный slug или не делай приложение публичным вымышленным SDK.

Ручной путь в исходном аккаунте проходит через `/app/store/plugin-directories`.
Открой вкладку «Подключение» (`?tab=connect`) и подтверди кабинет, затем в «Регистрации»
выбери папку. В «Моих плагинах» добавь зарегистрированный плагин в каталог и открой карточку.
Старый `bindAppToDeveloper` и общий ключ HTTP-hook закрыты; не добавляй временный маршрут
в плагин для вызова этого устаревшего метода.
