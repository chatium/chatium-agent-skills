# Поддержка скиллов

Формат поставки определи по [вопросам об исходниках, кастомизации и поддержке](../SKILL.md#выбери-формат-публикации).
Для шаблона используй отдельные инструкции по [упаковке скилла](templates.md#шаблон-со-скиллом)
и [установке из ZIP](templates.md#установить-скилл-из-шаблона). Для плагина
используй механизм `.skills` ниже.

## Скиллы внутри плагина

Платформа собирает скиллы из всех плагинов, установленных в целевом аккаунте.
В **корне каждого плагина** она обнаруживает каталоги скиллов в `.skills` и
передаёт каждый пакет целиком, включая его справочники, скрипты и ресурсы. Так
скилл поставляется и обновляется вместе с кодом плагина, независимо от карточки Store.

### Путь и имя

Размести каждый скилл отдельной папкой непосредственно внутри `.skills`. Имя
папки и `name` в YAML frontmatter файла `SKILL.md` должны совпадать:

```text
<корень плагина>/.skills/chatium-app-<appSlug>-<skillName>/SKILL.md
```

- `chatium-app-` — общий префикс для скиллов приложений.
- `appSlug` — фактический slug приложения без платформенного префикса `dev-`.
  Для `dev-sales-tools` используй `sales-tools`. Возьми slug из регистрации приложения,
  имя каталога исходников может отличаться.
- `skillName` — выбранное тобой имя возможности, например `deal-summary`. Используй
  строчные латинские буквы и цифры, разделяй части одиночным дефисом. Сохраняй полное
  имя стабильным, чтобы ссылки на скилл продолжали работать.

Например, у плагина `dev-sales-tools`, зарегистрированного из `solutions/crm`,
могут быть два скилла:

```text
solutions/crm/
└── .skills/
    ├── chatium-app-sales-tools-deal-summary/
    │   ├── SKILL.md
    │   └── references/
    │       └── crm-fields.md
    └── chatium-app-sales-tools-pipeline-report/
        └── SKILL.md
```

```markdown
---
name: chatium-app-sales-tools-deal-summary
description: Собрать сводку выбранной сделки CRM и предложить следующий шаг. Используй для запросов «что по сделке» и «напомни договорённости».
---

# Сводка сделки

Прочитай выбранную сделку и её доступную историю. Верни договорённости, открытые
вопросы и следующий шаг. Чтобы сопоставить поля, прочитай [поля CRM](references/crm-fields.md).
```

В `description` укажи, когда агенту применять скилл. В `SKILL.md` опиши входные
данные, последовательность действий и способ проверить результат. Детальные контракты
вынеси в `references/` и свяжи относительными ссылками внутри пакета. Включи все
файлы, нужные в аккаунте установки. Используй обычные файлы и каталоги.

### Связи между скиллами

В инструкциях ссылайся на соседний скилл или скилл другого приложения по **полному имени**.
Например: «Для подготовки рассылки используй `chatium-app-mailings-launch`».
Если скилл необходим для сценария, укажи приложение, которое его поставляет.
Проверь наличие скилла в целевом аккаунте перед обращением к нему. Если Mailings
или его скилл отсутствует, сообщи, какой зависимости не хватает, и продолжи
доступную часть работы. Относительные ссылки на файлы используй внутри своего пакета.

### Проверка в аккаунте установки

1. Проверь точное имя папки и `SKILL.md`. Убедись, что Git видит `.skills` и нужные
   файлы ресурсов. Проверь правила ignore, если каталог отсутствует в составе коммита.
2. Опубликуй согласованную версию кода плагина и проверь успешную сборку. Используй
   тестовый аккаунт с установленным плагином и доступной ему версией скилла.
3. В checkout **этого аккаунта** выполни `chatium get-skills`. Для Codex ищи
   `.agents/skills/chatium-app-sales-tools-deal-summary/SKILL.md`, для Claude Code
   `.claude/skills/chatium-app-sales-tools-deal-summary/SKILL.md`. Проверь, что рядом
   скачались используемые справочники и ресурсы. Платформа поставляет исходный пакет,
   а эти каталоги содержат локальные копии клиента.
4. Открой новый чат агента в том же аккаунте. Сначала обратись к скиллу по полному
   имени и проверь результат простым запросом без записи данных. Затем попроси
   о той же задаче обычными словами, чтобы проверить обнаружение по `description`.
   Для связанного сценария проверь доступность каждого скилла по полному имени.

Если файлов после обновления нет, проверь по порядку целевой аккаунт, установку
плагина, опубликованную сборку, корень `.skills`, slug и точный регистр `SKILL.md`.
Если файлы есть, а агент не справляется, проверь обнаружение по имени, относительные
ссылки, требуемые инструменты и доступ к данным в этом аккаунте.

## Поддержка в карточке Store

Поля карточки описывают возможности для поиска и фильтров. Файлы поставляются
как пакет внутри архива или исходников плагина. Правила описания одинаковы для обоих форматов.

`supportsSkills: true` включает отметку. `hasFunctionality` показывает, есть ли у решения
функциональность помимо скиллов. По умолчанию она есть. Для пакета инструкций без интерфейса
поставь `hasFunctionality:false`, сохраняя формат plugin или template. Пользователю показывай
единый признак поддержки, не создавай категории «только скиллы» и «со скиллами».

Каждый элемент `skills` содержит:

| Поле | Содержание |
| --- | --- |
| `id` | Стабильный ID описания в этой карточке, до 120 символов; сохраняй при обновлении |
| `title` | Понятное название возможности, до 200 символов |
| `description` | Что агент сможет сделать, с какими данными, ожидаемый результат, ограничения; до 12000 |
| `categoryIds` | Реальные ID из `getCreatorCatalogOptions().skillCategories` |
| `usage` | Необязательная инструкция до 4000 символов: подготовка, примеры запросов, ограничения доступа |

Не добавляй `file`, `path`, `hash`, содержимое SKILL.md или URL загрузки. SDK отклоняет
неизвестные поля. Метаданные не заменяют реальную реализацию скилла.

Выбирай функциональные категории карточки и категории скиллов независимо. Например,
CRM-плагин может относиться к CRM, а его скиллы — к продажам и аналитике. Не создавай новые
категории на лету: агент читает существующий справочник; редактирование справочника остаётся
административным. Для заявки у каждого скилла нужна минимум одна категория.

Пример описания: «Сводка сделки» — собирает историю общения и задачи выбранной сделки,
выделяет договорённости и следующий шаг. Usage: «Откройте сделку и попросите агента:
“Подготовь сводку и следующий шаг”. Нужен доступ к CRM. Отправка сообщений клиенту требует
отдельного поручения». Не обещай отправку, права или данные, которых реализация не поддерживает.
