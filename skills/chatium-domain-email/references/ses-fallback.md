# Временная резервная отправка через SES

Используй **после настройки домена/почты и проверки конкретного письма**, если
отправка с наших IP не удаётся или получатель подтвердил попадание в спам.
Предложи резерв на период [прогрева домена](warmup.md), до увеличения объёма.
При обычном успешном подключении отдельно включать резерв не требуется.

## Разбери результат перед предложением

Сначала выполни [проверки подключения](verification.md), прочитай доступные статусы
письма, SMTP-ответы и отбивки. Отчёт текущего аккаунта — `/app/email/delivery-report`;
для конкретной отправки смотри «Подробности» и историю попыток. Если публичного SDK
для отчёта нет, прочитай его через авторизованный интерфейс. Прямое подключение
к внутренней базе CES не является частью клиентского сценария.

Исправь выявленные ошибки DNS, аутентификации, транспорта и адреса получателя.
Письмо в очереди, таймаут диагностики и неизвестный результат ещё не означают
подтверждённый отказ. Сначала выясни состояние уже созданной отправки.

Текущая настройка — **разрешение резервного маршрута**, а не принудительная
отправка каждого письма через SES. CES может использовать его после подтверждённого
отказа SMTP с наших IP, исчерпания временных попыток или недоступности наших маршрутов
для MX, если сам домен допущен к отправке через SES. Разрешение действует для всего
домена и **по умолчанию выключено**.

Если письмо уже принято сервером и затем попало в «Спам», предложи обсудить временный
резерв, но объясни его границу: **одна эта галочка не переключает такую отправку
на SES и не переносит письмо во «Входящие»**. В публичном SDK этот метод не задаёт
основной маршрут SES. Если нужен именно он, передай оператору домен и ID примера
для проверки поддерживаемого способа; не выдумывай параметр `provider: 'ses'`.
Приём письма SES также не гарантирует попадание во входящие у получателя.

## Прочитай настройку и получи решение администратора

```ts
import { getEmailDomainStatus } from '@email/sdk'

const domain = 'example.com' // Проверяемый домен, полученный из транспорта.
const status = await getEmailDomainStatus(ctx, { domain })
const sesPermissionRead = status.success === true && status.domain === domain &&
  status.connected === true && typeof status.sesFallbackEnabled === 'boolean'
return {
  domain,
  sesPermissionRead,
  enabled: sesPermissionRead ? status.sesFallbackEnabled : null,
  error: status.success === true ? null : (status.error || 'domain_status_unavailable'),
}
```

Отсутствующее поле означает неизвестное состояние, а не `false`; ошибка API —
не сохранённую настройку. При недоступном методе/поле проверь опубликованную версию
SDK и доступ, сохрани конкретное ограничение. Обход через служебный ключ не нужен.

Если резерв выключен и есть подходящее основание, задай один вопрос администратору
аккаунта, которому принадлежит домен. Например, после подтверждённого отказа SMTP:

> Почта [домен] настроена и проверена, но сервер получателя отклоняет письмо
> с наших IP. Разрешить временную резервную отправку через Amazon SES на период
> прогрева? Настройка действует на весь домен: SES сможет использоваться,
> если отправка с наших IP не удалась.

Для случая спама назови фактический результат и объясни ограничение выше.
Пользователь принимает решение в чате; настройку через SDK выполни сам.
При уже включённом резерве или ранее полученном явном разрешении для этого домена
повторный вопрос не нужен. Отказ сохраняет резерв выключенным и не блокирует
остальную работу с почтой. Роль Admin сама по себе не заменяет решение о включении.

## Сохрани и проверь

После явного разрешения администратора вызови
`setEmailDomainSesFallback(ctx, { domain, enabled: true })` из **`@email/sdk`**.
Метод требует Admin и проверяет принадлежность домена текущему аккаунту. Он меняет
только разрешение: не подключает заново домен, не изменяет DNS/MX, не отправляет
письмо и не повторяет прежнюю отправку.

Проверь `success === true`, точный `domain` и `sesFallbackEnabled === true`
в результате записи, затем повтори чтение примера выше. Подтверждение сохранения —
`sesPermissionRead === true` и `enabled === true` при повторном чтении. После таймаута
сначала перечитай настройку. `forbidden` требует администратора, `domain_not_connected`
возвращает к настройке подключения; другие ошибки разбери по фактическому ответу.

Состояние «резерв разрешён» ещё не доказывает отправку через SES. Продолжи проверку
прежнего письма по его ID. Для нового теста используй согласованного получателя
и сохранённый идентификатор новой отправки. Принятое письмо, письмо в спаме или
письмо с неизвестным исходом не переотправляй автоматически ради смены маршрута.
Разрешение SES не отменяет отписки, блокировки адресатов или согласованный объём.

В отчёте проверь фактический маршрут `ses`, статус и ответ сервера, а после приёма
сервисом — доступный результат доставки/отбивку. Папку у Gmail, Яндекса или Mail.ru
проверяй отдельно. Сообщи: разрешение сохранено или нет; какой маршрут использован;
письмо ожидает, принято сервисом, доставлено или получен отказ; известна ли папка.

## Возврат к обычной отправке

Продолжай постепенный прогрев по наблюдаемым результатам. Доставка через SES
не доказывает готовность наших IP для этого домена. После успешных прямых проверок
предложи отключить временный резерв: тот же метод с `enabled: false`, затем повторное
чтение с подтверждённым `false`. Используй заранее согласованные условия отключения
или получи решение; произвольного срока «домен прогрет через N дней» не назначай.
Автоматического срока действия у настройки нет. Отключение не отменяет и не
переотправляет письма, уже переведённые в очередь SES.
