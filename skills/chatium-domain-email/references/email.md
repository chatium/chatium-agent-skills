# Подключение Chatium Email

## Приложение, права и существующая почта

Публичный импорт — **`@email/sdk`**, приложение открывается по `/app/email`.
`@app/email` — другой, системный API отправки, не API подключения этого приложения.
Методы настройки Email требуют Admin текущего аккаунта; SDK работает через функции
установленного приложения. Передавать `accountId`, ключ CES или cookie браузера не нужно.

Сначала проверь серверный импорт и чтение через `chatium exec` в целевом аккаунте.
`node_modules/@email` — локальные типы, а не реестр установленных приложений.
`chatium get-typings` загружает зависимости по импортам в исходниках проекта:
если `@email/sdk` используется только в одноразовом exec, его типов может не быть
даже после обновления. Обновление typings не публикует новые серверные методы.

Если базовые методы SDK работают, Email доступен. Один успешный импорт или наличие
экспортов этого не доказывает: публичный модуль может загрузиться, а вызов `app.function`
вернуть `path not found`, если приложение не подключено в аккаунте.
Отсутствие `email` в каталоге Store или ошибка поиска этого slug не опровергают
успешное чтение через SDK. При ошибке импорта или вызова проверь точный импорт
и доступность `/app/email` в авторизованной сессии;
отличай отсутствие приложения от отказа доступа и ошибки загрузки.
Для подтверждённо отсутствующего приложения предложи подключение доступным в аккаунте
способом. Если оно найдено в Store и установка поручена пользователем, следуй
[Store SDK](../../chatium-development/store-plugin-install.md). Отрицательный ответ
каталога не является основанием перебирать slug или обходить установку внутренним API.
Ошибка `forbidden` требует нужной роли, а ошибка настройки сервиса — исправления
подключения администратором; служебный ключ CES не запрашивается в чате и не копируется
из аккаунта-публикатора.

Снимок состояния и доступности нужных методов:

```ts
const sdk = await import('@email/sdk')
return {
  accountId: ctx.account.id,
  accountName: ctx.account.name,
  emailApi: {
    getEmailState: typeof Reflect.get(sdk, 'getEmailState') === 'function',
    enableEmail: typeof Reflect.get(sdk, 'enableEmail') === 'function',
  },
  domains: await sdk.listEmailDomains(ctx),
  transports: await sdk.listEmailTransports(ctx),
}
```

Проверяй `success` каждого ответа. `domains.domains[].isReady` относится к привязке
домена, а не доказывает готовность почты. Найди транспорт выбранного домена; сохрани
его `id`, `from`, `senderName`, `active`, `isDefault`, callback и настройки отписки.
`transportId` — **внутренний `transport.id` из SDK**, не ключ Sender или externalId.
`ces.enabled` означает сохранённую привязку, а не свежее подтверждение доступности.

Для уже подключённого домена `getEmailDomainStatus(ctx, { domain })` читает состояние.
`connected:false, setupRequired:true` без `ready` означает, что подключение ещё нужно
настроить; отсутствие поля не равно успешной проверке. Этот метод подходит для
первичной диагностики. `checkEmailTransportDns` обращается к подготовке/проверке
домена в почтовом сервисе; используй его в сценарии настройки выбранного транспорта.

## Создай или переиспользуй транспорт

Домен должен принадлежать этому аккаунту. Для нового собственного домена сначала
выполни [привязку](domain.md). Если задача только про почту, сохрани существующие
сайт и DNS; `External` позволяет зарегистрировать домен без управления ими.
Уже зарегистрированный в Email домен может отсутствовать в списке доменов сайта:
проверь текущий транспорт/ответ Email, не создавай лишнюю привязку ради обхода ошибки.

Для нового транспорта:

```ts
import { createEmailTransport } from '@email/sdk'
return await createEmailTransport(ctx, {
  domain: 'example.com',
  title: 'Почта поддержки',
  senderName: 'Поддержка Example',
  emailUsername: 'support',
})
```

Подставь согласованные значения. Повтор создания по домену возвращает существующий
транспорт и не обновляет его поля. Для изменения используй
`updateEmailTransport(ctx, { transportId, senderName, emailUsername, ... })` с нужными
полями; не перезаписывай callback, active или шаблоны отписки без задачи на их изменение.
Домен существующего транспорта не меняется — другому домену нужен другой транспорт.
Для обычного домена создание транспорта само по себе не подключает почту.
Только что созданный транспорт собственного домена держи неактивным на время
подготовки DNS: `updateEmailTransport(ctx, { transportId, active: false })`.
Это правило не отключает ранее работавший транспорт; его состояние сохраняется
до согласованного изменения. Системный домен обрабатывается по отдельной ветке ниже.

## DNS, подключение и активация

1. Вызови `checkEmailTransportDns(ctx, { transportId })`. Ответ содержит `success`,
   а при успешной проверке — `ready`, `connected` и `checks` с `{ name, type, value,
   ok, purpose }`. Разбирай фактическую ошибку вместо продолжения с отсутствующими checks.
2. По [правилам DNS](dns.md) подготовь и внеси нужные записи. В частности, проверь
   `ownership`, `dkim`, `spf`, `dmarc`, `inbound`, `bounce`, `bounce-spf`, если они
   присутствуют в ответе. Полагайся на текущий набор checks, а не на постоянный список
   MX/селекторов. Чужой действующий inbound MX не заменяется ради зелёного статуса.
3. Повторяй проверку с ограничением из основного сценария. Пока `ready !== true`,
   выводи конкретные `checks` с `ok !== true`; недоступность сервиса учитывай отдельно
   от ещё не распространившихся DNS-записей.
4. Когда DNS готовы, вызови `connectEmailTransport(ctx, { transportId })`.
   Для успешного подключения нужны **`success === true`, `ready === true` и
   `connected === true`**. Этот вызов настраивает привязку и служебные callbacks Email;
   произвольный `setEmailTransportCallback` для подключения не нужен.
5. Перечитай транспорт. Для задачи включить отправку добейся `active === true`
   через `updateEmailTransport(ctx, { transportId, active: true })`, если требуется.
   Установка `active` не исправляет DNS и не заменяет подключение.
6. Только если пользователь выбирает этот канал основным, вызови
   `setDefaultEmailTransport(ctx, { transportId, isDefault: true })`. Это сбрасывает
   default у других email-транспортов. Затем перечитай **весь список** и проверь,
   что выбран ровно нужный default; `default_update_partial` означает неполную операцию.

Заверши свежим чтением по [проверке почты](verification.md#почта).
После таймаута connect сначала перечитай `getEmailDomainStatus` и `getEmailTransport`;
повтор допустим для того же домена/транспорта, без создания дубля.

Для нового подключения не используй устаревшие `enableMailing`, `getMailingState`,
`setDomainMxRecord` из `@app/account/domain` и закрытый `setEmailPlatformMx` из Email.
Они не являются альтернативным путём к новому почтовому сервису. `legacy_setup_retired`
означает необходимость использовать текущий сценарий Email, а не повторять старый API.

## Системный домен

Определи системный домен по данным SDK, а не по наличию слова `chatium` в имени.
Не регистрируй его как новый собственный домен и не требуй доступа к NS платформы.
Создание такого транспорта может сразу инициировать его подключение: проверяй
возвращённое `connection`, затем заново читай транспорт и состояние сервиса.

`system_dns_pending`, `system_profile_unavailable` и `mail_profile_conflict` требуют
соответственно ожидания/действия оператора или разбора уже выбранного профиля.
Сохрани рабочий транспорт. Не переключай профиль и не редактируй родительскую DNS-зону
для обхода ошибки. Если SDK не подтверждает готовность системной почты, сообщи это.

## Почтовый ящик

Адрес `transport.from` — адрес отправителя, он не доказывает существование ящика.
Если пользователь просит приём в конкретный общий ящик, после подключения домена
вызови `listEmailMailboxes(ctx, { transportId })`. Для отсутствующего адреса:

```ts
import { createEmailMailbox, listEmailMailboxes } from '@email/sdk'
const transportId = 'TRANSPORT_ID' // реальный внутренний id из SDK
const created = await createEmailMailbox(ctx, { transportId, mailbox: 'support@example.com' })
if (!created.success) return created
return await listEmailMailboxes(ctx, { transportId })
```

Проверь в повторном списке точный адрес, домен и `active === true`. Создание повторно
не должно менять пароль, алиасы и доступы. SDK создаёт **общий служебный ящик**;
личные ящики сотрудников настраиваются в интерфейсе Email под нужным пользователем.
Пароли SDK не принимает и не возвращает. Не создавай ящик только ради проверки
исходящего транспорта, если он не входит в задачу.

Настройка ящика не доказывает фактический приём: при необходимости выполни
[согласованный тест обмена письмами](verification.md#обмен-тестовыми-письмами).

## Включи почту аккаунта

Для работы с ящиком в приложении «Почта» (`/app/email`) нужно включить почту аккаунта. `connectEmailTransport`
подключает домен и транспорт к CES, а `createEmailMailbox` создаёт адрес в CES.
Они сами по себе не включают доступ аккаунта к почте. Поэтому созданный активный
ящик может одновременно существовать с экраном «Почта не включена».

Прочитай `getEmailState(ctx)`: результат содержит `success` и `state`
с `accountId`, `enabled`, `domains`, `mailboxes`. Это проверка теми же учётными данными
и с теми же правилами видимости, что использует интерфейс; секреты и письма не возвращаются.

Если нужен ящик и `state.enabled === false`, вызови `enableEmail(ctx)`.
Это отдельное идемпотентное включение почты аккаунта — та же операция, что кнопка
«Включить почту». Она не создаёт адресов, не меняет DNS/транспорт и не отправляет писем.
Затем заново вызови `getEmailState`: нужны `enabled:true`, правильный аккаунт
и запрошенный активный ящик в доступном списке. Пустой список после включения требует
создания отсутствующего адреса или разбора доступа к уже существующему; пересоздание
активного ящика в CES не исправляет права чтения.

Если базовые методы работают, а `emailApi` показывает отсутствие этих экспортов,
сообщи, что в текущем серверном SDK они недоступны. Количество экспортов и версия
файла скилла не определяют номер версии Email. Новые методы становятся доступны
после публикации приложения Email; произвольный поиск «обновления приложения» через
Store и повторный `get-typings` этот шаг не заменяют.

В таком случае открой `/app/email` и используй «Включить почту» либо попроси пользователя
нажать эту кнопку, затем проверь наличие нужного ящика. До такой проверки сообщай:
«Домен и ящик настроены; доступ к почте ещё не подтверждён». Служебные таблицы,
ключи CES и внутренние HTTP-маршруты не являются заменой публичного SDK.

Заверши [проверкой доступности почты](verification.md#почта-и-доступ-к-ящику).
