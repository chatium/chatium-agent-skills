# Translation System Examples

## Basic Usage

```ts
// Simple translation
ctx.t('Open file')
// Returns: "Open file" (if no translation) or translated string

// With dynamic variable
ctx.t('Hello, {name}!', { name: user.name })
// Returns: "Hello, John!" or "Привет, John!" depending on ctx.lang
```

## Plural Forms

```ts
// English as key language
ctx.t('{count} {items(count)} found', {
  count: 5,
  items: {
    // keys here are plural form names from Intl.PluralRules.select() function (`zero`, `one`, `two`, `few`, ...) or specific numbers (0, 1, 1000, ...), special key $other is a fallback if no other matches
    one: 'item',      // 1 item
    $other: 'items',  // 0 items, 2 items, 5 items, etc.
  },
})
// Returns: "5 items found"

// Russian translation (ru.lang.yml):
// - key: '{count} {items(count)} found'
//   val:
//     $msg: '{count} {items(count)}'
//     count:
//       one: 'Найден {count}'
//       $other: 'Найдено {count}'
//     items:
//       one: элемент      # 1, 21, 101
//       few: элемента     # 2, 3, 4, 22, 103
//       $other: элементов # 0, 5, 11, 25, 100
```

or with a single selector:

```ts
// English as key language
ctx.t('{items} found', {
  items: {
    $val: 5,
    0: 'No items',
    one: '{$val} item',      // 1 item
    $other: '{$val} items',  // 0 items, 2 items, 5 items, etc.
  },
})
// Returns: "5 items found"

// Russian translation (i18n/ru.lang.yml):
// - key: '{items} found'
//   val:
//     $msg: '{items}'
//     items:
//       0: Ничего не найдено
//       one: 'Найден {$val} элемент'  # 1, 21, 101
//       few: 'Найдено {items} элемента' # 2, 3, 4, 22, 103
//       $other: 'Найдено {items} элементов' # 0, 5, 11, 25, 100
```

## Gender/Custom Selectors

```ts
// English key with gender selector
ctx.t('{name} {completed(gender)} the task', {
  name: 'Alice',
  gender: user.gender,
  completed: 'completed',
})
// Returns: "Alice completed the task"

// Russian translation (ru.lang.yml):
// - key: '{name} {completed(gender)} the task'
//   val:
//     $msg: '{name} {completed(gender)} задание'
//     completed:
//       male: выполнил
//       female: выполнила
//       $other: выполнил(а)
// Returns: "Alice выполнила задание"
```

## Parameterized Selectors

```ts
// One variable affects another
ctx.t('{count} {items(count)}. Delete {them(count)}?', {
  count: 3,
  items: {
    one: 'item',
    $other: 'items',
  },
  them: {
    1: 'it',
    $other: 'them',
  },
})
// Returns: "3 items. Delete them?"
```

## Ordinal Numbers

```ts
ctx.t('{name} finished {place}', {
  name: 'John',
  place: {
    $val: 23,
    $pluralType: 'ordinal', // 1st, 2nd, 3rd, 4th...
    one: '{$val}st',
    two: '{$val}nd',
    few: '{$val}rd',
    $other: '{$val}th',
  },
})
// Returns: "John finished 23rd"
```

## Specific Number Values

```ts
ctx.t('{count}', {
  count: {
    $val: foundItems,
    0: 'Nothing found',
    1: 'Found exactly one item',
    one: 'Found {$val} item',
    $other: 'Found {count} items',
  },
})
// Returns: "Nothing found" (if foundItems === 0)
// Returns: "Found exactly one item" (if foundItems === 1)
// Returns: "Found 5 items" (if foundItems === 5)
```

## Enum-like Selectors

```ts
ctx.t('Status: {status}', {
  status: {
    $val: order.status,
    pending: 'Waiting for payment',
    paid: 'Payment received',
    shipped: 'On the way',
    delivered: 'Delivered',
    $other: 'Unknown status: {$val}', // fallback with original value
  },
})
```

## Namespaces ($ns)

Use rarely, only for keys that may be translated differently in different contexts. Do not use by default.
```ts
// Different contexts need different translations
ctx.t('Close', { $ns: 'dialog' })    // "Close" button in dialog
ctx.t('Close', { $ns: 'finance' })   // "Close" financial period
ctx.t('Close')                       // "Close" in default context

// locales/en.lang.yml:
// dialog:
//   - key: Close
//     val: Close
// finance:
//   - key: Close
//     val: Close period
// default:
//   - key: Close
//     val: Close
```

## Static Context (t() function)

```ts
// Top-level module code without ctx
import { t } from '@app/i18n'

const STATUS_LABELS = {
  active: t('Active', { $ns: 'userStatus' }),
  inactive: t('Inactive'),
  banned: t('Banned'),
}

// Later in dynamic context with ctx:
const label = ctx.t(STATUS_LABELS[user.status])
// Returns translated string based on ctx.lang
```

## Lang File Format

```yaml
# Simple translations (belong to 'default' namespace)
- key: Open file
  val: Открыть файл

- key: Save
  val: Сохранить

# With dynamic variables
- key: 'Hello, {name}!'
  val: 'Привет, {name}!'

# With selectors
- key: '{count} {items(count)} found'
  val:
    $msg: '{count} {items(count)}'
    count:
      one: 'Найден {count}'
      $other: 'Найдено {count}'
    items:
      one: элемент
      few: элемента
      $other: элементов
```

Alternatively, use a namespace map as the file's root instead of a list:

```yaml
default:
  - key: Open file
    val: Открыть файл

dialog:
  - key: Close
    val: Закрыть
```

## Lang File Naming

Valid names:
- `ru.lang.yml` - Russian translations
- `en.lang.yml` - English translations
- `en_US.lang.yml` - US English (with region)
- `en-gb.lang.yml` - British English (hyphen also works)
- `ru.auto.lang.yml` - Auto-generated Russian (lower priority)
- `en.cms.lang.yml` - English with description part

Invalid names:
- `ru.lang.yaml` - wrong extension
- `cms.lang.yml` - no language code
- `main.ru.auto.lang.yml` - language code must be first

## Lang file location

Anywhere in the account codebase. Recommended locations: `i18n/`, `locales/`, `lang/` folder in account root or some sub-project folder.

## Adding Selectors in Translations

```ts
// English doesn't need gender selector
ctx.t('{name} completed the challenge', {
  name: student.name,
  gender: student.gender, // developer provides gender even if not used in English
})

// Russian needs gender selector
// ru.lang.yml:
// - key: '{name} completed the challenge'
//   val:
//     $msg: '{name} {completed(gender)} испытание'
//     completed:
//       male: завершил
//       female: завершила
//       $other: завершил(а)
```

## Simplifying Selectors in Translations

```ts
// Complex selector in code
ctx.t('You are on the {place} place', {
  place: {
    $val: rating,
    $pluralType: 'ordinal',
    one: '{$val}st',
    two: '{$val}nd',
    few: '{$val}rd',
    $other: '{$val}th',
  },
})

// Russian doesn't need ordinal forms
// ru.lang.yml:
// - key: 'You are on the {place} place'
//   val: 'Вы на {place}м месте'
// Selector simplified to simple variable
```

## Language Detection Priority

ctx.lang is determined by (highest to lowest priority):
1. `ctx.user.lang` - user's explicit choice
2. Mobile app language setting (only for requests from mobile apps)
3. `account.lang` - account default if explicitly set
4. `accept-language` HTTP header
6. `en` - fallback default

## Language Format

```ts
// Two formats supported:
// 1. Short: 'en', 'ru', 'uk' (ISO 639-1)
// 2. Full: 'en_US', 'pt_BR', 'ru_KZ' (language_REGION)

// Used in:
// - File names: en.lang.yml, en_US.lang.yml
// - ctx.lang value
// - ctx.user.lang
```

## Special Characters Escaping

```ts
// Escape { if needed in keys:
ctx.t('Use \\{braces} for variables')
// Returns: "Use {braces} for variables"

// in *.lang.yml:
// - key: 'Use \{braces} for variables'
//   val: 'Используйте \{фигурные_скобки} для переменных'

// Supported escapes: \", \\, \/, \{, \}, \b, \f, \n, \r, \t
```

## Variable Name Rules

```ts
// Valid variable names:
ctx.t('{userName}', { userName: 'John' })
ctx.t('{user_id}', { user_id: 123 })
ctx.t('{count2}', { count2: 5 })

// Invalid (only letters, digits, underscore): {user-name}, {user.name}, {user name}, {$custom}
// Note: $ is reserved for special variables like $val, $ns, $msg, $other, $pluralType
```
