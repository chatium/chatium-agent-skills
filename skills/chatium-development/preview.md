# Показ результата в превью

Когда пользователь просит «покажи», «открой», «дай посмотреть», открой
нужную сущность в панели превью. Также открывай её после завершения
согласованного изменения, когда результат доступен в интерфейсе. Одной
текстовой ссылки недостаточно, если инструмент открытия доступен.
Не переключай панель после каждого сохранения файла: показывай законченный
результат — страницу, письмо, статью или автоматизацию. Для серии писем открой её папку.

## Как открыть

В Chatium Code / DSH вызови `mcp__browser__browser_navigate` с полным URL
на **домене текущего аккаунта**. Этот браузер связан с панелью пользователя.
Используй доступную схему инструмента. В другом harness используй его
инструмент панели браузера (например, `open_in_codex` с browser URL в Codex).
Ссылка в ответе дополняет открытие. Если инструмент недоступен, дай полную
ссылку и прямо скажи, что открыть панель автоматически не получилось.

После навигации проверь адрес и заголовок/содержимое доступным инструментом
браузера: нужный ли объект, нет ли ошибки или редиректа на вход. Открытие
панели само по себе не доказывает загрузку страницы. При запросе входа
оставь страницу пользователю; не ищи его пароль и не меняй права доступа.
Просмотр редактора не требует нажимать «Сохранить», создавать рассылку или
отправлять письмо.

## Сущность → адрес

В таблице пути относительны текущему аккаунту, не хосту исходников плагина.
`encodeURIComponent` кодирует **значение**, не готовый URL целиком.

| Сущность | Адрес |
| --- | --- |
| Страница или лендинг | Реальный HTTP-маршрут страницы, например `/trial-class/register`; уточни по файлу маршрута и регистрации handler, не добавляй `.tsx` |
| Письмо `.mailings/storage/<path>.message.yaml` | `/app/mailings/#/letter/<encodeURIComponent(path + '.message.yaml')>` — весь путь относительно `.mailings/storage/`, включая вложенные папки и расширение |
| Автоматизация `*.automationConfig.json` | `/app/automations/~view?path=<encodeURIComponent(configPath)>` — путь к файлу конфига от корня аккаунта с расширением, без префикса `source-file:` |
| Самостоятельный AI-агент | `/app/agent-process/agent/<encodeURIComponent(agentId)>` — фактический `agentId` получи через SDK после публикации файла `*.agent.json`; экран требует роль Admin |
| Хранилище писем | `/app/mailings/#/store` |
| Папка писем/серия | Открой хранилище и выбери папку в его дереве/карточках по фактическому UI; прямой ссылки на выбранную папку пока нет |
| Статья `.knowledge-base/<path>.md` | `/app/knowledge/~/<path>.md` — убери префикс `.knowledge-base/`, сохрани структуру папок и расширение, кодируй каждый сегмент пути отдельно |

Маршруты письма и папки Mailings выше относятся к `.mailings/storage/`. Для существующих YAML-писем внутри процессного воркспейса `type: emails` используй фактический интерфейс превью процесса; не подставляй их путь в маршрут хранилища автоматически.

Примеры:

- `.mailings/storage/processes/trial-class/reminders/01-welcome.message.yaml`
  → `/app/mailings/#/letter/processes%2Ftrial-class%2Freminders%2F01-welcome.message.yaml`.
- `.knowledge-base/framework-chatium/chto-novogo/changelog.md`
  → `/app/knowledge/~/framework-chatium/chto-novogo/changelog.md`.

Для автоматизации передавай путь именно к файлу, а не к его папке или ID
экземпляра. Query собирай через `URLSearchParams`, чтобы `/`, пробелы и
другие символы пути были закодированы как значение `path`:

```javascript
const url = new URL('/app/automations/~view', accountUrl)
url.searchParams.set('path', configPath)
// /app/automations/~view?path=consult-booking%2Fautomations%2Freminders%2Freminders.automationConfig.json
```

Открой этот URL после завершения правок конфига или по просьбе показать
автоматизацию. Для просмотра не включай автоматизацию и не запускай её
шаги. Правила выбора опубликованной версии ниже применяются и здесь.

Письмо открывается в редакторе с просмотром Email, Чат и SMS. Нужное
представление выбирается в интерфейсе; отдельный URL-параметр режима не
предусмотрен. Просмотр шаблона не означает, что отправка уже проверена.

У Mailings состояние экранов хранится в hash: `#/letter/<путь>` — письмо,
`#/store` — хранилище, `#/list` — рассылки. На голом `/app/mailings/`
открывается список рассылок, а не письмо. `#/settings/<путь-папки>` —
**настройки** папки, не список её писем. Не выдавай этот экран за превью серии.
В текущем коде `#/store/<путь>` не выбирает папку: её выбор хранится отдельно
в памяти UI. Если папку не удалось открыть через UI, оставь хранилище и
укажи точный путь, не утверждая, что выбранная папка уже показана.

## Какая версия показана

Для Source Git сначала обеспечь доступность правок в разрешённой ветке.
Локальное сохранение не обновляет опубликованный интерфейс. Не публикуй
`main` только ради превью. Порядок публикации — в основном скилле.

Для просмотра опубликованной ветки добавь query-параметр
`__chtmPreviewMode__=account:<branch>` **перед hash**, сохранив другие
query-параметры. Например:

```javascript
const url = new URL('/app/mailings/', accountUrl)
url.searchParams.set('__chtmPreviewMode__', `account:${branch}`)
url.hash = `/letter/${encodeURIComponent(relativeLetterPath)}`
// https://<аккаунт>/app/mailings/?__chtmPreviewMode__=account%3Acodex%2Fdemo#/letter/series%2Fwelcome.message.yaml
```

Если для работы уже выбран preview плагина, сохрани его scope при
переключении аккаунта: например,
`app_start:agent/process-view-b,account:codex/demo`. Это одна cookie, поэтому
замена всего значения на `account:…` сбросит preview плагина. Пример выше
предполагает отсутствие дополнительных scopes.

Для `main` при переключении с другой ветки также выбери `account:main`,
чтобы прежняя preview-cookie не оставила пользователя в старой ветке.
`branch` как отдельный query-параметр не является общим переключателем
версий Mailings или базы знаний. Плагины могут читать данные из разных
хранилищ: после открытия сравни видимое содержимое с ожидаемой правкой,
не считай наличие preview-параметра доказательством свежести письма/статьи.
Если объект не найден или версия не совпала, сообщи это и проверь источник
данных; не создавай вторую копию в другом хранилище ради показа.

## Когда показывать

- После правки страницы — саму страницу по её маршруту.
- После правки автоматизации — её превью по пути к `.automationConfig.json`.
- После правки письма — это письмо; после работы над серией — её папку.
- После правки знаний — затронутую статью в reader; если статей несколько,
  открой основной обзор и дай ссылки на остальные.
- По явной просьбе показать сущность — открой её сразу в указанной ветке;
  без указанной ветки используй рабочую и сообщи, какую версию показываешь.

Моменты показа карты бизнес-процесса и её специальные параметры задаёт
скилл `processes`. Маршрут превью агентов пока не определён: не придумывай
его.

Маршруты Mailings сверены с `plugin/index.tsx`,
`plugin/mailings/send/components/MailingsSendApp.vue` (applyHash/setHash,
StoreScreen) и `LetterEditorScreen.vue` исходников Mailings. Если доступный
интерфейс отличается от этой версии, проверь его маршрутизацию.
