# Маршрутизация и передача разговора

Несколько самостоятельных агентов могут быть привязаны к одному каналу Sender. Без включённого маршрута входящее сообщение может попасть всем привязанным агентам. Для клиентского канала явно настрой одного первого получателя. Если разговор уже ведётся, маршрутизатор прежде всего сохраняет текущего ответственного, если его не переопределяет более приоритетное правило или назначение. Правила, назначения и цепочки живут в аккаунте и **общие для Git-веток**.

## Простой маршрут через публичный SDK

Используй `@ai-agents/sdk/process`. Эти операции предназначены для серверного кода аккаунта с ролью Admin. Они не создают диалог и не отправляют сообщение.

1. После публикации найди фактический `agentId` по пути файла через `getPublishedAgentBySourcePath(ctx, sourcePath)` и точный ID канала Sender; привяжи агента через `linkAgentToChannel(ctx, { agentId, channelId })`, если связи ещё нет. Сверь возвращённые ветку и SHA-256 с целевой публикацией.
2. Прочитай `getProcessChannelRouting(ctx, channelId)`. Он возвращает `config` (или `null`) и `linkedAgentIds`. Сохрани `config.updatedAt`; для отсутствующей записи версия — пустая строка.
3. Для простого маршрута вызови `configureProcessChannelRouting` с `defaultAgentId`, `enabled: true`, `fallbackAction: 'default'`, `expectedUpdatedAt` и `sharedStateAcknowledged: true`. Последнее поле явно подтверждает, что изменение затронет все ветки. Метод откажет, если версия изменилась, агент не привязан или в канале есть пользовательские правила. Цепочки и назначения он не перенаправляет.
4. Снова прочитай состояние и вызови `dryRunProcessChannelRouting` с тестовым `chainKey` нового клиента. Проверь `mode: 'selected'` и ожидаемый `agentId`; отдельно проверь ключ существующего тестового разговора. Dry-run не создаёт цепочку/назначение, но оставляет диагностическую метрику.

```ts
import {
  getProcessChannelRouting,
  configureProcessChannelRouting,
  dryRunProcessChannelRouting,
} from '@ai-agents/sdk/process'

const before = await getProcessChannelRouting(ctx, channelId)
if (!before.linkedAgentIds.includes(agentId)) throw new Error('Агент не привязан к каналу')
await configureProcessChannelRouting(ctx, {
  channelId,
  defaultAgentId: agentId,
  enabled: true,
  fallbackAction: 'default',
  expectedUpdatedAt: before.config?.updatedAt ?? '',
  sharedStateAcknowledged: true,
})
const result = await dryRunProcessChannelRouting(ctx, {
  channelId,
  chainKey: 'test-lead-001',
  text: 'Здравствуйте',
})
if (result.mode !== 'selected' || result.agentId !== agentId) throw new Error('Маршрут не совпал')
```

Это метод только для **простого адресата по умолчанию**. Если канал уже использует правила по тексту, A/B или особые назначения, разберись в действующей конфигурации и настрой её через административный интерфейс. Не удаляй правила ради успешного вызова SDK. `fallbackAction: 'ignore'` означает, что новое входящее без подходящего маршрута будет проигнорировано, а не передано другому агенту. Для отдельного запасного агента нужны явные правила. Наличие `config.enabled` само по себе не доказывает правильный выбор для конкретного клиента.

## Передача между агентами

Для известного ключа цепочки используй `redirectChain(ctx, { fromAgentId, toAgentId, chainKey, messageText })`; если есть контакты клиента и нужно разрешить ключ через CRM — `redirectChainByContacts`. `messageText` должен кратко сообщить следующей роли цель клиента, согласованные факты, обещанный следующий шаг и нерешённые вопросы. Не добавляй туда секреты или лишние персональные данные.

При передаче новая цепочка получает идентичность клиента, CRM-связь, идентичность чата и серверный `chainContext` предыдущей цепочки; модель выбирается из конфига **нового** агента. Старый разговор помечается как перенаправленный, а дальнейшие сообщения по его ключу проходят через перенаправление. Параметр `copyChainParams` устарел и не управляет этим переносом. Передача не создаёт общую базу памяти всех агентов: бизнес-статус и документы сохраняй в CRM/операционном источнике, а следующему агенту предоставляй разрешённый доступ к ним.

Перед вызовом проверь, что целевой агент опубликован и может работать с нужным каналом. После вызова проверь фактическую целевую цепочку и тестовое входящее. Если передача отклонена или прервана, не объявляй её выполненной; оставь человеку понятный путь возврата. Не создавай автоматический круг взаимных перенаправлений.

## Preview и инструменты

Конфиг агента и custom tools читаются из текущей опубликованной ветки аккаунта. Инструмент, зарегистрированный через `@start/agent/tools`, доступен в preview этой ветки сразу после успешной публикации; в main он не появится до публикации в main. При этом маршруты каналов, назначения, история цепочек и пауза агента не изолированы по веткам. Для испытания используй отдельные тестовые контакты/ключи и не перенастраивай общий боевой канал без согласованного окна.
