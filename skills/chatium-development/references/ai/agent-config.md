# Конфигурация самостоятельного агента

В Source Git каждый обычный агент — файл `*.agent.json`; редактируй файл и публикуй ветку. Не вызывай `getOrCreateAgentForWorkspace` или `updateAgentById` для записи конфига: Git-аккаунт их отклоняет. `department` включает другую схему оркестратора, поэтому для самостоятельных ролей его не добавляй.

Проверяй файл по публичной `JsonAgentConfigSchema` из `@ai-agents/sdk/process`. Схема допускает часть дополнительных полей для совместимости; успешный `safeParse` не доказывает качество инструкции, существование инструмента или возможность доставить ответ. Точный тип и актуальные поля смотри в typings текущей установки.

```ts
import { JsonAgentConfigSchema } from '@ai-agents/sdk/process'

const parsed = JsonAgentConfigSchema.safeParse(config)
if (!parsed.success) throw new Error('Некорректный конфиг агента')
```

| Поле | Практический смысл |
| --- | --- |
| `title`, `instructions[]` | Имя и собственные инструкции роли. Текст должен задавать решения, примеры и границы; длина не равна качеству |
| `model`, `temperature` | Модель и степень вариативности; список моделей получай через `findModelsList` |
| `enabledTools[]` | Только канонические ссылки `{accountId?, isWorkspaceTool, path, pattern}`; получай через `getEnabledToolEntry`, сверяй с каталогом опубликованной ветки |
| `knowledgeBase` | `{mode:'ids',ids:[...]}` или `{mode:'allAvailableToAgents'}`. `ids` — ID баз, не статей; права доступа сохраняются |
| `waitingToolEnabled`, `autonomyInstructions` | Разрешение агенту завершать ход и планировать продолжение; подробности — [автономность](autonomy.md) |
| `timeZone`, `quietHours`, `stopOnNonRepliedMessages`, `tokensLimitPerChain` | Часы, остановка после молчания и бюджет; согласуй с бизнес-правилом |
| `messageBuffer.idleMs`, `freezeAfterOutgoingMessage` | Ожидание пачки входящих и пауза после собственного сообщения |
| `scheduleMessagesEnabled` | Планирование первых сообщений; не включай только ради обычного ответа на входящее |
| `goal` | Условие достижения результата и действие после него; для передачи другой самостоятельной роли — `redirect2`, см. [передачу](routing-and-handoff.md#передача-между-агентами) |

`maxTokensPerChain` устарел; для новых конфигов используй `tokensLimitPerChain`. `isPaused` в Git-файле не управляет текущей общей паузой агента. Устаревший builder-validator из UI может требовать поля, которые публичная схема делает необязательными: не используй его как универсальную проверку минимального Git-конфига.

После публикации прочитай `getPublishedAgentBySourcePath(ctx, sourcePath)`, проверь ветку, SHA-256 исходного текста, модель и `agentId`. Каталог инструментов проверь в том же preview-контексте. Затем отдельной тестовой цепочкой проверь диалог и реальные эффекты. Для содержательной проверки роли в бизнес-процессе используй скилл `processes`: платформенная схема не оценивает полноту фактов и качество продаж.
