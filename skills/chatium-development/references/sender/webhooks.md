# Sender: входящие обновления

Используй для обработки сообщений, кнопок, событий групп и сырых transport updates. Перед реализацией обработчика проверь [подключение и выбор канала](entities.md#подключение-и-выбор-канала).

## ⚠️ КРИТИЧЕСКИ ВАЖНО: Правила работы с транспортами и вебхуками

**НИКОГДА не реализуй самостоятельно:**
- Подключение и регистрацию вебхуков в мессенджерах (Telegram, VK и т.д.) напрямую через их API
- Установку webhook-URL через методы вроде `setWebhook`, `bot.setWebhook()`, прямые вызовы Telegram/VK Bot API для регистрации хуков
- Создание кастомных endpoint-ов для приёма обновлений от внешних мессенджеров — если только пользователь явно не описал нестандартный сценарий и осознаёт, что делает

**Для обработки входящих обновлений** (сообщений, кнопок, событий канала и т.д.) используй хук `@sender/webhook-received` — он автоматически получает все обновления от уже подключённых транспортов без дополнительной настройки вебхуков. Для входящих сообщений в личных чатах 1 на 1 можно использовать `@sender/message-received`; он не подходит для групп, каналов и транспорта TelegramManager. Оба хука общие для аккаунта: сначала фильтруй `params.channel.id` (при необходимости `params.channel.source`) и сразу `return` для остальных каналов.

**Почему это важно:** Сендер сам управляет регистрацией вебхуков при подключении транспорта. Попытка настроить вебхук вручную нарушит существующую интеграцию и сломает приём сообщений.

## Подписка на обновления

Есть 3 способа подписаться на обновления:

1. Через хук message-received - если обновление касается входящего сообщения в личном чате 1 на 1. Не подходит для групповых чатов и каналов. Не работает с транспортом типа TelegramManager. Важно: этот хук общий на весь аккаунт и получает входящие сообщения от всех подключенных транспортов, поэтому в обработчике обязательно фильтруй `params.channel.id`/`params.channel.source` и пропускай только нужные каналы.
2. Через endpoint и указание callback в канале Sender. В этом случае можно получать любые другие обновления, которые может присылать канал связи (например, уведомления о доставке сообщений, прочтении, события в группах или каналах и т.д.)
3. Через хук webhook-received - универсальный способ получать любые обновления от любых каналов без необходимости настраивать отдельный endpoint. Срабатывает на каждый входящий вебхук, сырые данные доступны через `sourcePayload`. Рекомендуемый метод, если нужно обрабатывать обновления помимо входящих сообщений.

### Настройка хука message-received

ВАЖНО!!! Адрес хука должен быть ровно таким `@sender/message-received`!!! Иначе ничего не сработает.
ВАЖНО!!! `@sender/message-received` срабатывает на все входящие личные сообщения аккаунта по всем подключенным транспортам. Никогда не передавай сообщение агенту или бизнес-логике без ранней фильтрации по нужному каналу: сначала проверь `params.channel.id` (предпочтительно) или `params.channel.source`, и сразу `return` для всех чужих каналов.
Обрати внимание! Если тебе нужно получать обновления без сообщений, то нужно использовать другой подход (webhook-received) - например для получения колбека. Или другого обновления, в котором нет входящего сообщения.

```typescript
import type { SenderMessageReceivedHookParams } from '@sender/sdk'

app.accountHook('@sender/message-received', async (ctx, params: SenderMessageReceivedHookParams) => {
    const allowedChannelIds = new Set(['my-channel-id'])
    if (!allowedChannelIds.has(params.channel.id)) return

    // Обработка входящего сообщения
    // После фильтра выше сюда попадут сообщения только из нужных каналов.
})
```

### Настройка собственного endpoint

Для этого нужно создать POST роут, а затем установить его через апи `updateChannel`.

```typescript
// custom-sender-endpoint.ts
export const customUpdatesHandlerRoute = app.post('/', async (ctx, req: app.Req<{channelId: string, sourcePayload: unknown}>) => {
    const {channelId, sourcePayload} = req.body

    const originalUpdateData = sourcePayload; // Исходные данные от канала связи в соответствии с документацией канала

    // Обработка входящего запроса от канала связи
    return { success: true };
});
```

Для установки endpoint нужно вызвать метод `updateChannel`:

```ts
import { updateChannel } from '@sender/sdk';
import { customUpdatesHandlerRoute } from './custom-sender-endpoint';

try {
    return await updateChannel(ctx, {
        id: channelId,
        callback: customUpdatesHandlerRoute.url() //  для сброса указать null
    });
} catch (error) {
    console.error('Ошибка настройки callback канала:', error);
    throw error;
}
```

### Настройка хука webhook-received

Самый простой способ подписаться на **любые** обновления от любого канала. Вызывается на каждый входящий вебхук независимо от его типа.

ВАЖНО!!! Адрес хука должен быть ровно таким `@sender/webhook-received`!!! Иначе ничего не сработает.

`chatId` и `messages` — **опциональны**: не все вебхуки связаны с конкретным чатом или сообщением (например, уведомления о доставке, события канала, callback-кнопки и т.д.). Не рассчитывай на их наличие — используй `sourcePayload` для получения сырых данных.
Обрати внимание! Если хочешь использовать сырой chat id, то не передавай его в sendMessageToChat, т.к. этот метод требует внутренний chat id (от сендера) - а его априори не может быть в sourcePayload. Для отправки сообщения по такому id тебе нужно либо сначала найти чат, либо использовать метод sendMessageByTypeAndExternalId, который позволяет отправлять сообщения по внешнему id (например, telegram chat id) без необходимости сначала находить внутренний chat id.
А также не забывай про метод runTelegramApi, который позволяет вызвать напрямую апи телеграм, используя настроенный канал (это может быть актуально, например, чтобы поставить реакцию, отредактировать сообщение, отправить опрос и т.д).

```typescript
// Минимальная форма хука: публичного экспортируемого типа для неё нет.
type SenderWebhookReceivedHookParams = {
  channel: { id: string }
  chatId?: string
  messages?: unknown[]
  sourcePayload: unknown
}

app.accountHook('@sender/webhook-received', async (ctx, params: SenderWebhookReceivedHookParams) => {
    // Зачастую нужно отфильтровать по channel.id, чтобы обрабатывать обновления только нужного канала
    if (params.channel.id !== 'my-channel-id') return

    const rawUpdate = params.sourcePayload; // Исходные данные от канала в соответствии с его документацией
})
```
