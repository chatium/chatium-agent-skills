# Mailings SDK

Плагин Mailings предоставляет `@mailings/sdk` для работы с сохранёнными письмами из серверного кода. Для чтения используй `readMessageFile`, для отправки — `sendMessageFromTemplate`. Не обращайся к файлам напрямую и не воспроизводи отправку через другие API. Перед использованием проверь экспорты и типы установленной версии SDK.

## Чтение письма

```typescript
import { readMessageFile } from '@mailings/sdk'

const raw = await readMessageFile(ctx, 'series/welcome.message.yaml')
// raw.content — исходный YAML

const parsed = await readMessageFile(ctx, 'series/welcome.message.yaml', {
  parse: true,
})
// parsed.content — объект с содержимым письма
```

Передай путь письма относительно директории Mailings; полный путь, полученный из Mailings, тоже подходит. Метод возвращает `{ path, content }`: без флага `content` — строка YAML, с `parse: true` — объект. При неверном пути, отсутствии письма или ошибке разбора метод выбрасывает исключение.

## Отправка письма

```typescript
import { sendMessageFromTemplate } from '@mailings/sdk'

const result = await sendMessageFromTemplate(ctx, {
  messageKey: 'series/welcome',
  contacts: [{ type: 'email', value: recipientEmail }],
  variables: { firstName },
})
if (!result.success) throw new Error(result.error ?? 'Не удалось отправить письмо')
```

`messageKey` — ключ письма относительно директории Mailings, обычно без
`.message.yaml`. `contacts` задаёт исходных получателей разных типов;
`variables` и `segment` необязательны. SDK выбирает вариант и проверяет
обязательные переменные. `expandCustomerContacts: true` передаёт Sender
поручение добавить уникальные контакты недостающих типов через CRM.
Правила расширения, ограничения и приоритета —
[sendMessageToContacts](sender/messaging.md#sendmessagetocontacts).
Не копируй эту логику в Mailings или в действие процесса.

Проверяй `success`, `error`, `errorCode`, `channelResults` и `warnings`.
Предупреждение `AMBIGUOUS_CONTACT_TYPE` означает, что несколько адресов одного
типа не добавлены автоматически. Ошибка CRM, отсутствие/неоднозначность клиента или превышение
лимита расширения также возвращаются в `warnings`, сохраняя отправку исходным
контактам. Поле `contactType` в предупреждении необязательно. Общий успех
не подтверждает доставку всем получателям; не повторяй всю отправку после
частичного успеха. Ошибки RPC или
схемы вызова могут отклонить Promise; ошибки обработки шаблона возвращаются
как `success: false`.

### Настройки бизнес-процесса

Для ключа `processes/<process>/...` SDK читает `.workspace.json` указанного
процесса через SDK Start:

- `config.senderChannels` — непустой список ID выбранных каналов. Перед
  отправкой он обязателен. Явный `channels` вызова может только сузить этот
  список; настройки шаблона не расширяют его. Отсутствие каналов не запрещает
  проектирование/сборку процесса: процессный `check` показывает предупреждение.
- `config.mailings.testOnly` — обязательный boolean. Пока процесс не запущен,
  оставляй `true` и заполни `config.mailings.testContacts` контактами `{type, value}`.
  Mailings сверяет явно переданные контакты с этим списком до вызова Sender.
  При нарушении отправка отменяется целиком. Пока `testOnly: true`, параметр
  `expandCustomerContacts: true` запрещён: CRM может добавить реальный контакт.
  Расширение доступно после согласованного отключения тестового режима.
  `analyticsMode: 'test'` не заменяет эту защиту.

Для шаблонов вне `processes/` настройки процесса не применяются; каналами
управляет `channels` вызова, затем поле шаблона. Передавай выбранные каналы
явно. Получателя, ссылку, дату, сумму и другие бизнес-данные может готовить
одно индивидуальное действие, которое затем вызывает SDK. Отдельный шаг
подготовки и общий экшен автоматизаций не обязательны.

### Разработка SDK

Публичные функции `readMessageFile` и `sendMessageFromTemplate` только
вызывают `app.function`. Вся проверка путей, чтение, разбор YAML, выбор
варианта и ограничения выполняются в живом обработчике плагина. Импортируемое
тело SDK кэшируется в аккаунте потребителя; не оставляй там парсинг или
бизнес-правила. Старые версии SDK с локальным парсингом требуют однократного
обновления сборки потребителя. Для новых параметров обнови установленный SDK
и typings; Sender с новым контрактом должен быть опубликован до Mailings,
который передаёт ему защиту тестовых получателей.

## Показать письмо или папку пользователю

Открывай интерфейс плагина Mailings на домене текущего аккаунта по
[правилам превью](../preview.md). Путь для `#/letter/` относителен
`.mailings/storage/` и **включает** `.message.yaml`; это не `messageKey`
метода отправки. Экран письма содержит Email/Чат/SMS-превью. Папка серии
выбирается через UI хранилища `#/store`, а не выдуманным URL папки.
Открытие существующего письма не запускает рассылку.
